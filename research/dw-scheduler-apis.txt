Purpose and Scope 
This page documents the new scheduler APIs introduced by Folia to replace the single-threaded BukkitScheduler . These APIs ensure tasks execute on the correct thread context in Folia's regionized multithreading environment. 
For information about the folia-supported flag requirement, see 3.1 Compatibility Requirements For understanding thread safety principles when using these schedulers, see 3.3 Thread Safety Guidelines For practical migration guidance from BukkitScheduler to the new schedulers, see 3.4 Migration Guide

Overview 
Folia has no main thread. Instead, each region has its own tick loop executing at 20 TPS in parallel README.md 18-22 The traditional BukkitScheduler API, which assumes a single main thread, cannot function in this environment and is deprecated folia-api/paper-patches/features/0002-Region-scheduler-API.patch 33-41 Folia introduces four specialized scheduler types:

RegionScheduler 
Purpose 
RegionScheduler schedules tasks to execute on the region tick thread that owns a specific location README.md 95-97 This is the primary scheduler for location-based game logic. 
API Methods 
The RegionScheduler interface provides location-based task scheduling: 
run(Plugin, Location, Consumer<ScheduledTask>) 
runDelayed(Plugin, Location, Consumer<ScheduledTask>, long delayTicks) 
runAtFixedRate(Plugin, Location, Consumer<ScheduledTask>, long initialDelayTicks, long periodTicks) 
Thread Context 
Tasks execute on the region tick thread currently owning the specified location. If the location is not loaded, the task will not execute until the region becomes available README.md 133-137 
Sources: README.md 88-96 README.md 154-157 folia-api/paper-patches/features/0002-Region-scheduler-API.patch 6-7 
EntityScheduler 
Purpose 
EntityScheduler schedules tasks to execute on the region tick thread that owns a specific entity README.md 95-97 This scheduler follows the entity as it moves between regions. 
API Methods 
Retrieved via Entity#getScheduler() . Methods include: 
run(Plugin, Consumer<ScheduledTask>, Runnable retired) 
runDelayed(Plugin, Consumer<ScheduledTask>, Runnable retired, long delayTicks) 
runAtFixedRate(Plugin, Consumer<ScheduledTask>, Runnable retired, long initialDelayTicks, long periodTicks) 
The retired callback executes if the entity is removed (e.g., despawned) before the task runs. 
Thread Context 
Tasks execute on whichever region tick thread currently owns the entity. As entities move between regions, scheduled tasks automatically transfer to the new region's thread. 
Sources: README.md 88-96 README.md 154-157 folia-api/paper-patches/features/0002-Region-scheduler-API.patch 6-7 
AsyncScheduler 
Purpose 
AsyncScheduler provides true asynchronous execution off the region tick threads. This is the only scheduler for operations that must not block region ticks, such as I/O or database access README.md 54-60 
API Methods 
Retrieved via Bukkit.getAsyncScheduler() . 
runNow(Plugin, Consumer<ScheduledTask>) 
runDelayed(Plugin, Consumer<ScheduledTask>, long delay, TimeUnit unit) 
runAtFixedRate(Plugin, Consumer<ScheduledTask>, long initialDelay, long period, TimeUnit unit)

GlobalRegionScheduler 
Purpose 
GlobalRegionScheduler schedules tasks to execute on the global region tick thread. This thread handles server-wide operations that do not belong to any specific world region, such as console commands README.md 167-169

BukkitScheduler Deprecation 
The BukkitScheduler interface is marked @Deprecated in Folia folia-api/paper-patches/features/0002-Region-scheduler-API.patch 33-41 
Replacement Mapping 
BukkitScheduler Method Folia Replacement runTask() RegionScheduler.run() (Location-based) runTask() EntityScheduler.run() (Entity-based) runTask() GlobalRegionScheduler.run() (Global) runTaskAsynchronously() AsyncScheduler.runNow() runTaskLater() [Type]Scheduler.runDelayed() runTaskTimer() [Type]Scheduler.runAtFixedRate() 
Why Deprecation is Necessary 
The BukkitScheduler API assumes a single main thread and that all "sync" tasks can safely access all game data. In Folia, regions tick in parallel, and data is isolated README.md 115-121 Accessing data from the wrong region thread will result in an IllegalStateException README.md 126-128
