Folia implements a region-based threading model that requires strict adherence to thread ownership rules. This page documents the core thread safety mechanisms that prevent cross-region data access and ensure operations execute on the correct threads. 
Overview 
Folia divides the world into regions, with each region owned by a specific TickThread . All access to region-owned data (entities, chunks, blocks) must occur on the owning thread. The thread safety system provides three layers of protection: 
Thread ownership validation : TickThread.isTickThreadFor() methods. 
Thread enforcement : TickThread.ensureTickThread() methods throw IllegalStateException on violations. 
Safe access patterns : RegionizedData<T> for region-local storage and task scheduling for cross-region communication.

Region-Based Thread Ownership 
Each ThreadedRegion is owned by a single TickThread during its execution. The TickRegionScheduler.getCurrentRegion() method returns the region currently executing on the calling thread, or null if called from a non-region thread folia-server/paper-patches/features/0001-Region-Threading-Base.patch 127-128 
Thread Ownership Determination Algorithm 
The isTickThreadFor() implementation for chunks: 
Retrieve currentRegion from TickRegionScheduler . 
If null , check if the thread is RegionShutdownThread . 
If not null, retrieve the targetRegion from the world's ThreadedRegionizer using getRegionAtUnsynchronised(chunkX, chunkZ) . 
Compare currentRegion == targetRegion . 
For multiple chunks (AABB or radius), the system calculates the section range using regioniser.sectionChunkShift and iterates through all involved sections to ensure the current region owns every one folia-server/paper-patches/features/0001-Region-Threading-Base.patch 133-151

Data Isolation via RegionizedWorldData 
Instead of global lists, Folia uses RegionizedWorldData to store world state that must be isolated per region.

RegionShutdownThread Special Handling 
The RegionShutdownThread is a special TickThread subclass that allows the server to perform cleanup and saving across all regions during shutdown. 
When isTickThreadFor is called and no region is currently active on the thread ( currentRegion == null ), the system checks isShutdownThread() . If true, the access is permitted folia-server/paper-patches/features/0001-Region-Threading-Base.patch 87-89 This bypasses the standard region-match requirement to allow the shutdown process to iterate through all world data sequentially.

Thread Safety in Entity Interaction 
Folia adds specific checks to entity interaction logic to prevent cross-region entity access. For example, when checking for intersections with EnderDragonPart , Folia adds a TickThread.isTickThreadFor(part) check to ensure the part is owned by the current region before processing the collision folia-server/minecraft-patches/features/0001-Region-Threading-Base.patch 41-50 
This pattern is pervasive: 
Entity Searching : Predicates are updated to include thread ownership checks.
